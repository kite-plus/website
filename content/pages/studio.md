后台是一个编译进二进制的 React 应用，没有东西要装，也不用和服务端对版本。在空文件夹里运行 `kite run` 时，它会先打开建站页面，问的就是 `kite init` 在终端里问的那些。

| 页面 | 做什么 |
| --- | --- |
| **仪表盘** | 已发布多少、还有多少草稿、有哪些改动没提交，以及按月的发布趋势 |
| **内容** | 文章和页面，通过索引而不是文件系统来过滤和搜索 |
| **编辑器** | 可视化编辑，读写的都是 Markdown，一键切到源码；实时预览、front matter 表单、分类标签、地址、字数，图片直接拖进文章的目录 |
| **分类法** | 标签和分类在全部内容里的真实分布，可以改名、合并和删除 |
| **主题** | 项目里的全部主题，启用前都能在整站上预览；上传 zip 安装主题；在实时预览旁边调整当前主题的设置 |
| **插件** | 上传 zip 安装插件，开关、修改设置、删除 |
| **部署** | 把网站导出成 zip，或者查看推送到 GitHub Pages 进行到了哪一步 |
| **设置** | 站点的标题、描述、地址、语言、作者、关键词、时区、搜索引擎收录和全站附加代码；后台自己的语言和配色；你的账户 |

后台界面支持简体中文和 English，按浏览器语言选择，也可以在设置里指定。

## 写作

1. 在「内容」里新建文章或页面，用可视化编辑器写作，也可以切换到 Markdown 源码。
2. 拖入图片，设置分类、标签和文章地址。
3. 写作期间它是草稿；准备好了点「发布」。发布时间设在将来，文章就成了定时发布，到那个时间才会公开。

本机用 `kite run` 时会显示草稿，方便预览；正常运行站点和静态构建都会排除草稿和还没到时间的文章。

## 不会覆盖别人的改动

加载之后又在磁盘上变过的内容，会被拒绝写入而不是被覆盖，后台会明说这件事。你可以在编辑器里写，也可以同时在别的编辑器里改同一个文件，谁也不会悄悄吞掉谁的改动。

## API

后台做的每一件事，都走 `/api/v1` 下的同一套 HTTP API，而这套 API 由二进制自己描述：

```bash
kite openapi > openapi.json
```

`--admin` 提供这套 API，`--write` 允许它改动项目；不加 `--write` 时同一套 API 是只读的。后台的类型化客户端由这份描述生成，并在 CI 里校验，所以它编译时依赖的类型不可能描述一个服务端并不提供的 API。
